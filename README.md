# ドットパック（公開用）

GitHub Pages でサイトを配信し、投稿・投票・お問い合わせなどの書き込みだけを Firebase に保存する構成です。

```
index.html        公開ページ
admin.html        管理画面（管理者の Google アカウントだけが操作できる）
css/style.css     見た目
fonts/            BestTenDOT（ドットフォント）
js/config.js      ← Firebase の設定と管理者の UID を書くファイル
js/fb.js          Firebase の読み込み（本番と確認モードの切り替え）
js/fbreal.js      本物の Firebase
js/cards.js       カードの描画・星の決め方・パックの引き方
js/app.js         公開ページの動き
js/admin.js       管理画面の動き
js/mockfb.js      確認モード用（Firebaseの代わり。?mock のときだけ使う）
tools/serve.ps1   かんたん確認.bat が使う小さなサーバー
かんたん確認.bat  このパソコンで確認するためのファイル
packs/            締め切ったパックの JSON（月末に追加していく）
firestore.rules   Firestore のセキュリティルール
```

## はじめにやること

### 1. Firebase のプロジェクトを作る

1. [Firebase コンソール](https://console.firebase.google.com/) で、ドットパック専用のプロジェクトを新しく作る（大喜利サイトとは分ける。料金プランは無料の Spark のまま）。
2. **Authentication** → 「始める」→ ログイン方法で **匿名** と **Google** を有効にする。
3. **Firestore Database** → 「データベースを作成」→ 場所は **asia-northeast1（東京）**。あとから変えられません。
4. プロジェクトの設定 → マイアプリ → **ウェブアプリを追加**。表示された `firebaseConfig` の `apiKey`・`authDomain`・`projectId`・`appId` を `js/config.js` に書く。

### 2. GitHub に上げる

1. GitHub に公開リポジトリ（例：`dotpack`）を作り、このフォルダの中身をそのまま上げる。
2. リポジトリの Settings → Pages → Branch を `main` / `(root)` にして保存。数分で `https://ユーザー名.github.io/dotpack/` で開けるようになる。
3. Firebase の Authentication → 設定 → **承認済みドメイン** に `ユーザー名.github.io` を追加する。

### 3. 管理者を登録する

1. `https://ユーザー名.github.io/dotpack/admin.html` を開き、自分の Google アカウントでログインする。
2. 画面に出た **UID** をコピーする。
3. `js/config.js` の `ADMIN_UID` と、`firestore.rules` の `YOUR_ADMIN_UID` の2か所に、その UID を書く。
4. `js/config.js` を GitHub に上げ直す。
5. Firebase コンソール → Firestore → **ルール** に `firestore.rules` の中身を貼り付けて「公開」。

### 4. 最初のテーマを始める

admin.html の「テーマ」タブで、テーマ名・月・3つのパレット（各15色）を決めて「このテーマを始める」。これで公開ページから投稿・投票ができるようになります。

## このパソコンでかんたんに確認する（Windows）

`かんたん確認.bat` をダブルクリックして、番号を選びます。ブラウザが開きます。

- **1：Firebaseなしで試す**　Firebase の設定をする前でも、投稿・投票・締め切り・パック開封まで一通り試せる「確認モード」です。データはそのブラウザの中にだけ保存されます。画面下の黒い帯から、確認用データを消したり確認モードをやめたりできます。
- **2：Firebaseにつないで試す**　`js/config.js` を書いたあとに、本物の Firebase で試します。`localhost` は最初から Firebase の承認済みドメインに入っています。
- **3：管理画面を開く（確認モード）**　テーマ作り・締め切り・お問い合わせ対応を試せます。確認モードで締め切ったパックは、そのまま「パック」タブに並びます。

終わるときは黒い画面を閉じてください。インストールは不要です（Windows に入っている PowerShell を使います）。
確認モードは URL の末尾に `?mock` を付けたときだけ動くので、公開したサイトの動きには影響しません。

## 月末にやること

1. admin.html の「お問い合わせ」「作品」で、残っている依頼や、申告のない既存作品の二次創作を片付ける。
2. 「締め切り」タブで票の重みを確かめ、「集計して締め切る」を2回押す。
3. `0001.json` のようなパックのファイルと `index.json` の2つがダウンロードされる。
4. GitHub の `packs` フォルダに2つとも上げる（`index.json` は置き換え）。数分で「パック」タブに並ぶ。
5. 「テーマ」タブで次のテーマを始める。

締め切ったパックの作品をあとから非表示にしたときは、「パック書き出し」タブで作り直して、同じように `packs` のファイルを置き換えてください。

Firestore に残っているカードのデータは消さないでください。お問い合わせ（作者名の非表示など）の確認に使います。容量は1枚約1KBなので、無料枠の心配はありません。

## 無料枠のための工夫

- サイト本体とパックは GitHub Pages から配信するので、Firebase の転送量を使わない。
- 受付中のカードは、前回から変わった分だけ読み込む（ブラウザに保存）。
- 投票は手元にためて、3秒おき・ページを閉じるときにまとめて保存する。

## 試していないこと

- 本物の Firebase とセキュリティルールでの動作はまだ確かめていません。画面の流れ（テーマ作成→投稿→投票→締め切り→パック開封→図鑑）は、確認モードで確認済みです。
- 公開前に、Firestore のルール画面の「ルールのプレイグラウンド」か、実際に2つのブラウザ（片方はシークレットウィンドウ）で投稿・投票・お問い合わせを試してください。

## パックを開けられる回数の調整
`js/config.js` のいちばん下で変えられます。
- `PACK_CHARGE_HOURS`：何時間ごとに1回ふえるか（いまは3）
- `PACK_MAX`：時間でたまる回数の上限（いまは4）
- `PACK_PER_VOTE`：ほかの人の作品に投票したとき、1枚につきふえる回数（いまは1。上限なし。同じ作品は1回だけ）

回数は端末のブラウザに保存されます。Google連携している人はサーバーにも保存され、どの端末でも同じ回数になります。
